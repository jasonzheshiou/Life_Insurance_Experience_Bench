Act 1 · Three cases — you are the marker

The answer I am asking you for

One book, ten years, four benefit lines. Every answer has to say four things, or it does not count:

{
  "benefit":   "Death",
  "years":     [2018, 2024],
  "pattern":   "drift",        // drift | shock | volatility | recovery
  "direction": "increase",
  "magnitude": "+0.15/yr, A/E 0.66 -> 1.31",
  "evidence":  ["ae_death_by_year.csv: monotone rise, CI unchanged"],
  "recommended_action": "refer Death frequency to pricing and reserving"
}

Scoring is strict: benefit + pattern + window + direction must all agree with the planted truth. One wrong pattern word = a miss and a false alarm. Duplicates ignored, and on a clean book any claim at all is a false alarm.

drift

a sustained year-over-year move across 2+ years. May revert at the end — still drift.

shock

an abrupt level change with no build-up: flat-topped or a single year.

volatility

more year-to-year scatter, level unchanged. The one everybody calls a spike.

recovery

IP termination rate for one diagnosis moves; incidence untouched.

Act 2 · Methodology · the instrument

The harness: three parts, one variable

1 · Evidence pack stats_pack.py

Deterministic statistics computed from the same CSVs before the call: trend gradient and R², best step, non-overlapping excursion windows, onset ratio, longest run, 3-year smoothed series, tail segment, per-line overdispersion, cross-line swing coordination. It shows evidence, not verdicts — and says so.

2 · Rulebook HARNESS_RULES · 5 021 chars

The taxonomy, the output schema, and discipline clauses about what does not count: mild overdispersion is normal texture; a z of 3 in one year is ordinary; a small age cell is not evidence; anything you are not claiming must not appear as its own entry.

3 · Pinned system prompt + up to 4 sandboxed calls

Prompt lives in a file so it can be versioned without touching the runner. The model may run python -I -c against the scenario folder — 10 s, 4 000 chars of output.

the 2 × 2 design — nothing else varies

no harnessown harness
Qwen3.6-27B59.5 % acc · 40.0 % FP65.8 % · 38.7 %
Qwen3.8-27B64.0 % acc · 65.7 % FP71.2 % · 41.9 %

Same weights, same endpoint, same sampler (temp 1.0, top_p 0.95, top_k 20), one generation at a time on one llama.cpp slot, three runs each. Both subjects share the 27 B architecture — so every difference between them is behaviour, not capacity.

The sandbox is advisory, not enforced — we say so out loud

run_sandboxed_python() has a timeout and an output cap and sets the working directory. There is no rlimit, no network block, no filesystem jail. A direct probe showed model-authored code could enumerate the truth manifests. All 97 tool calls the campaigns recorded stayed inside artifacts/ — because the model chose to. If you rebuild this, put a real jail in before you run anything untrusted.

Act 2 · Methodology · the agentic part

A model grew the harness. Under rules.

1Runthe frozen harness over the 23 optimization books. Keep the corpus: prompt, answer, tool log, per-unit scorer diff.
2Read the wreckagefor each failed unit, say why it failed. Evidence, not vibes: the recorded prompt, the answer, the diff.
3One hypothesis, one edita new block in stats_pack.py, one discipline clause, or a new pinned prompt. Never two at once.
4Validate offline firstregenerate all 23 packs and diff them; confirm the CLEAN book and every solved book are untouched; run the leak preflight. Zero API calls.
5Re-run that one book ×3a single-book run costs ~10–40 min; a full 23-book pass costs 2 h (3.6) to 7 h (3.8).
6Keep or revertagainst a pre-registered bar. A failed edit is reverted, not massaged. Three edits died this way in the 3.6 campaign.
7Snapshot the bytescode and prompt copied into harness_snapshot/ with hashes before the next run, so any number can be traced to the instrument that made it.
✕Nevernever tune against heldout; never let a held-out result influence an edit. The held-out split is mounted once and spent.

Who typed the code? The loop was driven by a third model — DeepSeek V4.1 Flash, deliberately not one of the two subjects, so no subject tuned the exam it later sat. It produced 7 harness versions for 3.8 (v1.0 → v1.6e) from 307 per-scenario diary entries, 268 of which involved reviewing or editing the harness; two kept edits for 3.6 from the same base.

The two limits I will not hide

A human chose which failures to chase — the model proposed and applied, it did not set the agenda. And the frozen bytes prove which harness produced which numbers, not who typed each line. The runbooks narrate that; the narrative is not the evidence.

The declined fix

After the freeze gate passed, a better wording was found ("extend the same finding's window into the tail" instead of "add a second finding"). It was deliberately not applied — editing the instrument right after it passes the bar it just certified is precisely how a tuning set gets overfitted.

Act 2 · Methodology · the marking

Two ledgers, and a gate fixed in advance

metricformulathe question
accuracy (strict recall)hits ÷ unitsdid it find what was there?
FP/claimfalse alarms ÷ claimswhen it spoke, how often was it wrong?
precisionhits ÷ claims = 1 − FP/claimhow far can you trust it out loud?

Worked example — 3.8 with its own harness

units         111
strict hits   79
false alarms 57
claims       79 + 57 = 136
accuracy = 79 ÷ 111 = 71.2 %
FP/claim = 57 ÷ 136 = 41.9 %
precision = 79 ÷ 136 = 58.1 %

A unit is one planted control in one run; a book-wide control expands to one unit per benefit line. Accuracy and FP/claim never add to 100 % — different denominators. In the units ledger accuracy + miss = 100 %; in the findings ledger precision + FP/claim = 100 %. Reporting one of the two hides half of what happens.

The freeze gate — agreed before any tuning

  • strict recall ≥ 80 %
  • false alarms ≤ 1.0 per answer
  • zero anomalies claimed on the CLEAN book
  • zero unparseable answers, zero errored runs
  • no regression on the two drift strata vs the zero-shot reference — this is the clause that stops a harness buying recall by trading away a real skill

Exit status 0 or 1. Nothing in the gate calls the LLM. A human did later choose to lift the 3-pass cap — legitimate, but only because the held-out books stayed unread.

A sign-off based on the tuned numbers would have been wrong by about 30 points — for both models. An optimisation split is a ranking device. It is not a forecast.

Accuracy alone crowns 3.8. Precision crowns 3.6. Neither is wrong: 3.8 finds more and invents more; 3.6 finds less and lies less. Which is "better" is a question about your cost of a miss versus your cost of a false alarm — not a question about models.

Act 4 · Why this matters

You do not govern a model. You govern the pair.

Before anyone signs an LLM off for experience work, four questions have to be answered — and one convincing demo answers none of them:

1 · How good is it?

how much of what is really in the data does it find — on books nobody tuned on

2 · What does it miss, and what does it invent?

two different failures, priced differently, fixed differently — they cannot be averaged into one score

3 · What does one answer cost?

time and tokens, printed beside the result they bought, never in an appendix

4 · Is the pipeline around it right?

and on what evidence would you say the wrapper is still fit for purpose

Why the pair, and not the model

3.6 and 3.8 share a 27 B architecture — parameter count, weight size, compute graph, same serving slot, same sampler. Everything that differs is behaviour. How eagerly it asserts. How much it checks before speaking. Whether it reaches for a tool at all.

So when a vendor ships a new version, what changes is exactly the thing your harness was compensating for. Behaviour moves when a model is retrained even when its architecture does not.

The sentence to refuse

"We upgraded the model." That is a notice, not an assessment. A new version inherits an unproven harness, not a working one — and here the tuned harness was worth +23.8 precision points to one version and +1.3 to the next.

Priced the way you already price things

A miss is a deterioration nobody looks at — the error that ends up in a reserve. A false alarm is a quarter of an analyst's morning and a bit of credibility for whoever repeats it. Your ratio between those two is the model choice: 3.8 (finds more) if a miss dominates, 3.6 (invents less) if a false alarm does. That is an actuarial judgement, not a technology one.

The workflow the numbers actually support

  1. harness computes the evidence pack overnight — deterministic, no model, no cost
  2. model returns structured findings against a schema (~13.5 min/answer at 3.8 — a batch job, not a chat window)
  3. every finding carries the file and rows it relied on, so a human checks the claim, not the reasoning
  4. the reviewer's verdict is logged — that log is next year's regression test

Note what is not automated: the pattern judgement stays with the model only because we could verify it here. Where there is no answer key, this is a drafting aid, full stop.

Why the schema matters more than the IQ

Four fields, four allowed pattern words, one rule about what must not appear. That contract is what made this measurable at all — and it is the part you can copy into your own stack this quarter without buying anything.

Act 4 · Why this matters · the limits

What is honest to claim from this, and what is not

Two subjects, one serving stack

"The harness must be re-derived per model" is a real signal at real replication cost — but it is two models, both Qwen-lineage 27 B, one llama.cpp slot. It is not a general theory of harness portability. Two more subjects on a different stack would change what I am willing to say out loud.

Synthetic, by construction

Real books have mix shifts, system changes, reinsurance distortions and cohort effects that a planted control does not reproduce. The skill measured here is "is this gap signal" — the same move as real work, on data whose difficulty I controlled and whose realism I did not.

A hit here is not good judgement

These patterns are planted, so a hit means recovering a known signal. A real experience study is a judgement call with no answer key — is this deterioration worth a pricing review — and this benchmark cannot measure that, no matter how many scenarios I add.

This exam is spent, and that is by design

The 24 held-out books are published with their answers, so they can never serve as an unseen test for anything that reads this repo. A new exam means generating new books with fresh controls. Benchmarks rot: four families are already saturated.

And the one I would repeat in any board paper: a tuning-split score is a ranking device, not a forecast. It overstated real performance by about 30 points here, for both models.

Act 5 · What a benchmark is for

A benchmark is not a leaderboard. It is a test fixture.

1 · An answer key that cannot be argued with

Truth is generated, never hand-curated. Nobody's judgement is buried in the labels, so a disagreement is about the model, not about who labelled the file.

2 · Comparability across time and vendors

Same 123 units, same scorer, same books, every configuration ever run. "Is the new model better for us?" becomes arithmetic instead of vibes.

3 · Regression detection on your own pipeline

Every harness edit here was validated by regenerating all 23 evidence packs and diffing them. That is a unit test for a prompt — the thing most teams have never built.

4 · Difficulty you can dial

Undetectable drifts, lookalike traps, clean books, coordinated multi-line events — set on demand, at a chosen distance from the noise floor.

5 · Cost and quality on the same slide

Tokens and wall clock are recorded per run, so the tool can be priced per experience study instead of described as "cheap".

The one property nothing else gives you

With a fixture you can answer "would anything have noticed?"

The 30-point optimism gap, the withdrawn transfer claim, the 18→0 chatter clause, the sc-e6ffa4 failure — none of those are discoverable from a demo. They are discoverable only because the same exam was re-run under a changed instrument and the difference was arithmetic.

What the fixture cost

  • stdlib-only stack, Python ≥ 3.11 — scorer, pack, gate, leak scan all run offline, no API key
  • a full 23-book pass: ~2 h (3.6) to ~7 h (3.8) on one consumer slot
  • every published number reproducible from the clone: ~135 MB, largest file 0.41 MB
  • the expensive part was never compute. It was the discipline to keep the exam clean.

Act 5 · Steal this

Six moves to build one for your own work

1 · Pick a task with a planted truth

Something where you can manufacture the answer: A/E anomalies, lapse distortions, reserving outliers, mis-scaled exposures, a policy-coding error in a cohort. If nobody can say what the right answer is, it is not benchable yet.

2 · Two zones, and a leak scan

Model-facing files get opaque ids; the answer key lives elsewhere and is hashed. Scan the question for answer-bearing words automatically, before any call. It will catch your own mistakes before it catches the model's.

3 · Families, and a trap set

Easy cases will saturate within one model version. Budget for lookalikes and at least one nothing-is-wrong case, or your accuracy number is measuring how often the model bothers to answer.

4 · A contract before a prompt

Small schema, closed vocabularies, strict matching, and an explicit rule that an unclaimed observation is a false alarm. A malformed answer is a miss. This is what makes marking mechanical.

5 · Two ledgers, three runs, cost logged

Recall and FP/claim, never blended. Three runs: single runs cannot separate a consistent failure from an unlucky one — several findings here reversed when the sample grew from 9 books to 23.

6 · Freeze a gate before you tune

Write the stopping rule first, tune on a split you will never report, mount the held-out exam once, and keep a byte snapshot of the instrument behind every number.

Where this project would go next — and where yours should start

New families for the surfaces where this move recurs: lapse and persistency, expense A/E, morbidity, reserve-adequacy deltas. Each is a new scenario family and a new section of the evidence pack — not a new benchmark, not a new scorer, not a new governance argument. The skill being tested was never "reads A/E tables". It is deciding whether a gap between actual and expected is signal.

Five things to remember

1 · Agentic coding is only real when it is measured

A loop that edits code against a test it cannot peek at, keeps or reverts on evidence, and snapshots the bytes behind every number. That is the version worth building — and the only version anyone will let you deploy.

2 · The model found a lot and invented a lot

71 % of what was planted, at 58 % precision — with 31 pure inventions and a false accusation on a book that had nothing in it. Great eyes; needs a rulebook about what deserves to be written down.

3 · The wrapper is part of the system

Worth +24 points of precision to one model, +6 points of recall to another, and it did not transfer either way. Re-measure the pair after every model change.

4 · Two failures, two remedies

Misses and false alarms have different denominators, different costs and different fixes. Which model is better is an actuarial decision about pricing those two errors — never a technology decision.

5 · Synthetic data's gift is a knowable truth

That is what makes measurement possible at all — and the realism debt is the price. Plant the traps, plant the empty book, and publish the failures.
